# Это тебе — сайт-открытка

Тёмный романтичный digital-подарок: конверт → письмо с фото → «Что будем
делать?» → мини-игра с сердечками → плавно проявляющаяся картинка в самом
конце → фильм/поделиться/ответить. Плюс отдельная панель редактора, где
весь текст, фото и настройки меняются без единой правки в коде — и теперь
эти изменения видят **все** посетители, на любом устройстве.

## Структура проекта

```
index.html              — сама открытка (то, что видит получатель)
admin.html               — панель редактора (то, что видишь ты) + живое превью
css/style.css             — стили открытки
css/admin.css              — стили редактора
js/storage.js                — общий слой данных: читает/пишет через сервер
js/site.js                     — логика открытки (экраны, конверт, игра, кнопки)
js/admin.js                     — логика редактора (форма, сохранение, превью)
data/data.json                    — содержимое открытки (сюда пишет редактор)
data/replies.json                  — ответы получателя (пишет форма «ответить»)
api/config.php                       — ЗДЕСЬ задаётся пароль редактора
api/save.php                          — сохраняет data.json (только с паролем)
api/replies.php                        — приём/чтение ответов получателя
images/                                  — можно держать тут исходники фото для себя
```

## Что изменилось: как теперь хранятся данные

Раньше всё содержимое открытки хранилось в `localStorage` браузера — то
есть только на том устройстве, где его сохранили. Теперь:

- содержимое открытки лежит на сервере, в файле `data/data.json`;
- сайт (`index.html`) при каждом открытии сам подгружает актуальный
  `data/data.json` — значит все посетители всегда видят одно и то же,
  независимо от браузера и устройства;
- редактор (`admin.html`) при нажатии «Сохранить» отправляет данные на
  сервер через маленький PHP-скрипт `api/save.php`, который и
  перезаписывает `data/data.json`;
- `localStorage` для общих данных сайта больше **не используется** —
  только пароль редактора временно хранится в `sessionStorage` этой
  конкретной вкладки браузера, чтобы не вводить его при каждом сохранении;
- ответы получателя («написать пару слов в ответ») тоже уходят на
  сервер — в `data/replies.json` — и их можно посмотреть в редакторе,
  в разделе «Ответы получателя».

Никакой сложной регистрации/личного кабинета нет — доступ к сохранению
защищён одним паролем, который ты сам задаёшь в `api/config.php`.

## Как это устроено технически (для понимания, не обязательно читать)

- Никакой базы данных (MySQL и т.п.) не нужно — данные хранятся в обычных
  JSON-файлах на сервере (`data/data.json`, `data/replies.json`). Это
  самый простой вариант, который работает на любом хостинге с PHP.
- Единственное серверное условие — на хостинге должен работать **PHP**
  (это есть практически на любом обычном хостинге; Node.js не нужен).
- Фотографии по-прежнему хранятся так же, как раньше — «встроенными» в
  сами данные (в виде base64-строки), просто теперь эти данные лежат в
  `data/data.json` на сервере, а не в localStorage браузера.

## Как запустить локально (для проверки перед публикацией)

Для локальной проверки понадобится PHP (не просто `python3 -m http.server`,
потому что теперь есть скрипты `api/save.php` и `api/replies.php`):

```bash
cd путь/до/папки/проекта
php -S localhost:8000
```

Затем открой в браузере:

- редактор: `http://localhost:8000/admin.html`
- сама открытка: `http://localhost:8000/index.html`

## Как редактировать содержимое

1. Открой `admin.html`.
2. Введи пароль редактора в поле вверху страницы (тот, что задан в
   `api/config.php`).
3. Заполни разделы: кому, первый экран, текст письма, фотографии, пункты
   меню «Что будем делать?», фото для экрана с фильмом, картинку в самом
   конце, настройки кнопок.
4. Нажми розовую кнопку **«Сохранить»** внизу — данные уйдут на сервер,
   и справа в телефоне обновится живое превью. Если пароль неверный или
   сервер недоступен — появится предупреждение с описанием ошибки.
5. Ссылка «открыть отдельно» — открывает саму открытку в новой вкладке,
   как её увидит получатель.
6. Раздел «Ответы получателя» — кнопка «Показать ответы» подгружает то,
   что получатель написал через форму на сайте.

## Новое: картинка в самом конце

В самом низу последнего экрана добавлена картинка, которая плавно
проявляется (лёгкое движение вверх + исчезновение прозрачности — в том
же стиле, что и остальные анимации сайта), когда получатель дролистывает
страницу до конца. Настраивается в редакторе, в блоке «Картинка в самом
конце»: можно включить/выключить, загрузить файл и задать подпись.

## Публикация на обычном хостинге

1. **Загрузи на хостинг всю папку целиком** — `index.html`, `admin.html`,
   папки `css/`, `js/`, `api/`, `data/` (и `images/`, если используешь).
   Структура папок на сервере должна остаться такой же, как здесь.
2. **Создай/проверь права доступа на запись** для папки `data/` и файлов
   в ней (`data/data.json`, `data/replies.json`) — PHP должен иметь право
   их перезаписывать. Обычно достаточно прав `755` на папку и `644` на
   файлы; если хостинг ругается на запись — попробуй `775`/`777` на папку
   `data/` (это можно сделать через файловый менеджер хостинга или по
   FTP, пункт меню обычно называется «Права доступа» / «CHMOD»).
3. **База данных не нужна** — специально выбран вариант с JSON-файлами
   вместо MySQL, чтобы не пришлось ничего создавать и настраивать в
   панели хостинга кроме самих файлов.
4. **Единственная обязательная настройка перед публикацией** — открой
   `api/config.php` и замени
   ```php
   define('ADMIN_PASSWORD', 'change-me-please');
   ```
   на свой собственный пароль. Без этого шага в редактор сможет зайти
   кто угодно, кто найдёт адрес `admin.html`.
5. Проверь, что PHP на хостинге включён (почти всегда включён по
   умолчанию) — этого достаточно, устанавливать что-то дополнительно не
   нужно.
6. После публикации открой `https://твой-домен/admin.html`, введи пароль,
   заполни содержимое и нажми «Сохранить» — теперь это сохранится на
   сервере и увидят все, кто откроет `https://твой-домен/index.html`.
7. Пришли получателю ссылку на `index.html` (саму `admin.html` ему,
   конечно, отправлять не нужно).

### Если сохранение не работает после публикации

- Проверь, что пароль в поле наверху `admin.html` совпадает с тем, что
  указан в `api/config.php`.
- Если ошибка про запись файла — почти всегда дело в правах доступа на
  папку `data/` (см. пункт 2 выше).
- Если фотографии большие и сохранение не проходит — попробуй сжать фото
  перед загрузкой или попроси поддержку хостинга увеличить
  `post_max_size`/`upload_max_filesize` (в `api/.htaccess` уже есть
  попытка увеличить их автоматически, но это работает не на всех
  хостингах).

## Важное примечание про мини-игру с сердечками

В тексте письма может фигурировать какое-то особое число (например,
9494 — количество дней/секунд/что угодно личное). Чтобы не заставлять
человека физически нажимать тысячи раз, реальное количество кликов в
игре подобрано так, чтобы было приятно играть (обычно 20–60 нажатий),
а итоговый текст всё равно показывает то самое «личное» число, которое
ты укажешь в редакторе.

## О визуальном стиле

Дизайн (тёмный сине-фиолетовый фон, розовые акценты, скруглённые
карточки, конверт, экран с сердечками) сделан в похожем настроении по
референсу, который ты прислал, но код и разметка написаны с нуля —
это не копия чужого сервиса, а самостоятельный маленький проект,
который полностью твой и который можно менять как угодно.

## Версия с сохранённым оригинальным оформлением
Эта сборка сохраняет исходный экранный сценарий проекта: вступление → конверт → письмо → меню → отдельный интерактивный/финальный экран. Проект намеренно не превращён в одностраничный лендинг. Персональные значения в стартовой конфигурации заменены универсальными и по-прежнему редактируются через админ-панель. В JSON оставлены расширяемые поля `meta`, `security`, `music`, `theme` и `sections`, чтобы дальнейшие функции можно было подключать без повторной смены формата данных.
